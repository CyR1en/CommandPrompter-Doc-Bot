CMDP Doc Bot - Design Specification

Historical record. This 2026-06-19 design predates ref0 and does not describe the current Go runtime. See the current platform architecture. The old product name, Python stack, and dependency choices below remain only to preserve the original proposal.

Date: 2026-06-19

Overview: A Discord bot that uses a sandbox LLM agent (via OpenCode Zen) to answer user questions about a Minecraft plugin. The bot uses Retrieval-Augmented Generation (RAG) with local clones of the documentation and source code repositories.

1. Architecture & Tech Stack

  • Language: Python 3.11+
  • Discord Framework: discord.py
  • AI / RAG Orchestration: LangChain
  • Vector Database: ChromaDB (Embedded, local file-based)
  • LLM Provider: OpenCode Zen (via OpenAI-compatible base URL)
  • Version Control: GitPython for managing local repository clones

2. Data Flow & Repository Syncing

The bot maintains local clones of the target GitHub repositories to ensure it always has the latest context.

  • Initialization: On startup, the bot clones or pulls the target repositories into a local ./data/repos directory.
  • Indexing: Markdown files (.md) and source code files (e.g., .java) are parsed, chunked, embedded, and stored in ChromaDB at ./data/chroma.
  • Polling Mechanism: A background asynchronous task runs at a configurable interval (e.g., every 10 minutes). It executes a git pull on the repositories. If new commits are detected, the changed files are re-indexed in ChromaDB.

3. Bot Interaction & Concurrency

The bot is designed to handle multiple users naturally and efficiently.

  • Trigger: Users invoke the bot by @mentioning it in a Discord channel.
  • Feedback: The bot immediately displays a "typing" indicator while processing the request.
  • Concurrency:
    • Uses discord.py's asynchronous event loop.
    • LLM calls use LangChain's async methods (ainvoke) to prevent blocking.
    • ChromaDB queries are wrapped in an asyncio thread pool executor to ensure the main event loop remains responsive to other users.

4. Agent Lockdown & Scope Restriction

To prevent the bot from acting as a general-purpose AI or hallucinating answers outside the plugin's scope:

  • Strict System Prompt: The LLM is instructed to act exclusively as a Minecraft plugin support agent. It must only use the provided context. If the answer is not in the context, it must reply with a standard fallback message (e.g., "I can only answer questions related to the plugin based on the provided documentation.").
  • Relevance Threshold: The vector search enforces a similarity score threshold. Queries completely unrelated to the codebase will return empty context, forcing the LLM to use the fallback response.

5. Rate Limiting

To prevent abuse and manage API usage:

  • Mechanism: In-memory sliding window tracker mapping Discord User IDs to request timestamps.
  • Limit: 5 questions per 10-minute window per user.
  • Response: Users exceeding the limit receive a polite rejection message indicating when they can ask their next question.

6. Deployment

The application is containerized for easy deployment and state management.

  • Docker: A lightweight Python Dockerfile installs all dependencies.
  • Docker Compose: A docker-compose.yml file orchestrates the container and manages environment variables.
  • Volumes: A local ./data directory is mounted into the container to persist the cloned repositories and the ChromaDB database across restarts.
  • Environment Variables (.env):
    • DISCORD_TOKEN
    • LLM_API_KEY
    • LLM_BASE_URL
    • REPO_URLS (Comma-separated list)
    • POLL_INTERVAL_MINUTES
